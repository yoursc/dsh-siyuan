## 一、高

### U1 开关小球硬编码 `#fff`：组开关在**两种主题下都不达标**，逐工具开关在暗色下不达标

`lib/client.js:56`：

```css
.dsy-switch .dsy-switch-knob{position:absolute;top:3px;left:3px;width:14px;height:14px;
  border-radius:50%;background:#fff;box-shadow:0 1px 2px rgba(0,0,0,.25);transition:transform .15s ease}
```

这是全表 72 行 CSS 里**唯一的裸色值**（另一处 `rgba(0,0,0,.25)` 是同一个球的投影）。
宿主在完全对应的位置用的是 token：

```css
/* @deepseek-ai/dsh-client-ui-primitives/lib/Switch.module.css:39,44 */
.thumb { background: var(--dsw-alias-label-primary-foreground); }
.switch[aria-checked='false'] .thumb { background: var(--dsw-alias-switch-thumb); }
```

实测（小球 vs 轨道，门槛 3:1）：

| 开关变体 | 亮色 | 暗色 |
|---|---|---|
| 逐工具 ON（轨道 `state-business`） | 4.23:1 ✅ | **2.33:1 ❌** |
| **组开关 ON（轨道 `state-success`）** | **2.28:1 ❌** | **2.28:1 ❌** |
| **危险组 ON（轨道 `state-warn`）** | **2.15:1 ❌** | **2.15:1 ❌** |
| 组开关 OFF（轨道 `border-l4`） | 1.45:1 ❌ | 9.75:1 ✅ |
| *[宿主] ON（轨道 `brand`）* | *18.90:1* | *18.08:1* |

三个 ON 变体里有两个**两种主题都失败**，第三个在暗色失败。宿主自己的开关是 **18.90:1 / 18.08:1**——
差了近 8 倍。

**根因有两层，缺一不可：**

1. **小球写死白色。** 宿主在暗色下的小球是 `--dsw-alias-switch-thumb = #adb2b8`（中灰）、
   ON 态是 `--dsw-alias-label-primary-foreground = #0f1115`（**近黑**）——都不是白色。
   本插件强行白球，在暗色亮蓝轨道（`#7aaaff`）上就只剩 2.33:1。
2. **轨道用了饱和的状态色。** 宿主 `Switch` 的 ON 轨道是 `--dsw-alias-brand-primary`——
   一个**单色、随主题反转**的填充（亮色 `#0f1115` 近黑 / 暗色 `#f9fafb` 近白）。
   正因为轨道是单色反转的，白色（或近黑）小球才能拿到 18:1。
   插件改用 `state-business` / `state-success` / `state-warn` 这些**中亮度饱和色**做填充，
   白球在数学上就不可能达标——这是 U3 的机制来源。

**修复方向**（二者需要一起定，不是单纯换 token）：
- 最小改动：小球改 `var(--dsw-alias-label-primary-foreground)`（修 ON 态暗色）；
  但亮色组开关（绿底白球 2.28:1）仍不达标，因为根因 2 还在。
- 彻底：ON 轨道改 `--dsw-alias-brand-primary`，小球用 `label-primary-foreground`，
  即**回到宿主 Switch 的配色**；组/逐工具的区分改用尺寸与位置，不靠色相。

**✅ 已修（U1a）**：小球改用宿主的那一对 token——OFF/mixed 用 `--dsw-alias-switch-thumb`，
ON 用 `--dsw-alias-label-primary-foreground`。暗色三个 ON 变体全部转绿。
**⬜ 未修（U1b）**：根因 2（轨道用饱和 `state-*`）保留，亮色组开关/危险组仍 2.28 / 2.15:1——
卡在一个设计决定上，理由见状态表下方。

### U2 焦点指示用了比默认态**更弱**的 token，聚焦后控件反而变淡

`lib/client.js:35` 与 `:90`：

```css
.dsy-input:focus{border-color:var(--dsw-alias-border-l2)}
.dsy-tool:focus-visible{outline:2px solid var(--dsw-alias-border-l2);outline-offset:2px}
```

token 强度顺序是 **l4 > l3 > l2 > l1**（编号越大越重），而输入框默认边框用的是 `l4`：

```css
/* :34 */ .dsy-input{...border:.5px solid var(--dsw-alias-border-l4);...}
```

于是聚焦时边框从 `l4`(16%) 换成 `l2`(10%)——**从视觉上"取消"了边框**。实测：

| 元素 | 亮色 | 暗色 |
|---|---|---|
| `.dsy-input` 默认边框 `border-l4` | 1.45:1 | 1.87:1 |
| `.dsy-input:focus` 边框 `border-l2` | **1.26:1** | **1.41:1** |
| `.dsy-tool:focus-visible` outline `border-l2` | **1.26:1** | **1.41:1** |
| *[宿主] 焦点兜底 `state-business-primary`* | *4.23:1* | *7.83:1* |

宿主三个首方控件的焦点实现完全一致，都用 `state-business-primary`：

- `Input.module.css`：`.wrap:focus-within{border-color:var(--dsw-alias-state-business-primary)}`
- `Checkbox.module.css:21` 与 `Switch.module.css:29`：`outline: var(--dsw-focus-ring-width) solid
  var(--dsw-focus-ring-color, var(--dsw-alias-state-business-primary))`——注意
  `--dsw-focus-ring-*` 在主题里**未定义**，所以实际生效的就是那个兜底值。

也就是说宿主全站的焦点色是**明确的蓝色 4.23:1**，本插件用了一个 1.26:1 的浅灰。
`lib/client.js` 里 `dsw-focus-ring` 出现 **0 次**。

另有两处缺口：`.dsy-btn` 与 `.dsy-switch` **完全没有焦点样式**（依赖浏览器默认焦点环）；
而首方 `Switch` 是有 `:focus-visible` 的。

**✅ 已修复**：两处 `border-l2` 改成 `state-business-primary`；给 `.dsy-btn` / `.dsy-switch` 补
`:focus-visible`（照宿主写法）。焦点 1.26:1 → 4.23:1（亮）/ 1.41:1 → 7.83:1（暗）。

## 二、中

### U3 一个颜色承担多重语义，且与 U1 同源

当前颜色语义：

| 颜色 | 含义 1 | 含义 2 | 含义 3 |
|---|---|---|---|
| 绿 | 徽标「可达 · v3.8.8」 | 徽标「token 已配置」 | 只读/写入/日记三组的 master ON |
| 蓝 | 逐工具开关 ON | 按钮主色边框 | —— |
| 琥珀 | `.dsy-msg.warn` 文案 | 危险组 master ON | —— |

两个具体后果：

1. **同一布尔状态（整组全开）在不同组呈现不同颜色**。三个组是绿、危险组是琥珀。
   用户无法区分"琥珀 = 全开"还是"琥珀 = 部分开启"——尤其 `mixed` 状态**只有小球位置差 9px**
   （`.dsy-switch.master.mixed .dsy-switch-knob{transform:translateX(9px)}` vs ON 的 `18px`），
   颜色是 master 与 tool 的唯一区分手段。
2. **琥珀色 master 是误操作陷阱。** 用户在别处已学会"琥珀 = 注意、还没完"
   （`:44-46` 的注释自己写明了这个语义）。看到危险组 master 是琥珀，会以为"这组有问题"，
   点一下想解决——但 `checked === true` 时点击是**全关**，会把两个删除工具一起关掉。

`lib/client.js:62-67` 的注释显示作者是有意选色的（"和红标题同框不刺眼"），
但"同框不刺眼"的代价是"同色不同义"。**目标规范：同一状态用同一颜色；组与逐工具的区分
靠尺寸与位置，不靠色相。**

### U4 `Card.header` 插槽语义不统一：primary 保存按钮出现在两个位置

`Card`（`:204-213`）的注释写"标题行（右侧可放按钮/徽标）"，但四个 header 装了四种东西：

| 卡 | `header` 内容 | 行号 |
|---|---|---|
| 连接 | 可达徽标 | `:664` |
| API token | token 徽标 | `:694` |
| **默认笔记本** | **按钮组（加载/保存/撤销）** | `:731-737` |
| 工具开关 | 文字计数 | `:774` |

后果：`保存地址`、`保存 token`、`保存开关` 都在内容下方，**只有 `保存笔记本` 在标题右侧**。
用户建立不了"保存按钮在哪"的空间记忆。截图里这张卡的两个按钮紧贴标题，与上下三张卡形成明显反差。

**规范**：`header` 只承担状态展示；primary 操作按钮一律放内容下方的 `.dsy-actions`。

## 三、低

- **U5 状态被复制进 class。** 宿主 `Switch.module.css` 开头的注释明确说明它**只**用 `aria-checked`
  驱动外观，理由是"视觉状态不可能与辅助技术读到的状态分歧"。本插件用 `.dsy-switch.on`
  + `aria-checked` 两套推导（`:223-227` 与 `:233` 都由同一 prop 算出，**今天不会分歧**，
  但结构上允许分歧）。属潜在风险，不是当前缺陷。
- **U6 注释里的对齐推导与实现脱节。** `.dsy-group-hint{padding-left:50px}` 注释称"与组名/工具名同列"：
  组名在 `42+8=50px`（对），工具名在 `42+10=52px`（差 2px）。**重点不是 2px**，是推导没跟着
  `gap` 从 8 改成 10 更新。数值推导应写成常量或断言，不要写在注释里。
- **U7 圆角全用裸 px，未跟随宿主 radius token。** 宿主 `--dsw-radius-md:12px`、`--dsw-radius-sm:8px`，
  插件写的 `border-radius:12px`（卡片）与 `8px`（输入框/工具行）**值是对的**，但
  `--dsw-radius-*` 在 `lib/client.js` 里出现 **0 次**。宿主调整圆角体系时插件不会跟。
- **U8 禁用态只有透明度。** `.dsy-btn:disabled{opacity:.5}` / `.dsy-input[disabled]{opacity:.55}`。
  API token 卡在只读来源下会出现三个禁用元素与一个可用按钮并排，用户扫过会数成"N 个操作"。
- **U9 工具开关卡占页面 66%。** 在提供的截图（573×1877）上，工具开关卡从 y≈620 到 y≈1850，
  约 1230px，占整页 66%；17 行 × 每行 2 行文字。而开箱默认全开意味着绝大多数用户不需要动它。
  属信息架构问题（配置频率差异巨大的内容铺平在同一平面），非缺陷。

## 四、**不是**本插件的问题（继承自宿主，不要单方面改）

这一节是本次评审最需要克制的地方。下面每一条都能算出"不达标"，但**宿主自己就是这么做/这么选的**。
单方面"修好"会让插件偏离宿主设计语言，且宿主将来修了插件会自动继承。

| 现象 | 实测（亮色） | 为什么不算插件缺陷 |
|---|---|---|
| `.dsy-note` / `.dsy-count` / 工具名 / 徽标默认文字的 `label-tertiary` | 3.71:1 | 宿主全站用 `label-tertiary` 做次要文字（`Input.module.css` 的 icon、各 settings 页），同款取舍 |
| `.dsy-msg.ok` / `.dsy-badge.ok` 的 `state-success` 作文字 | **2.28:1** | 宿主把 `state-success-primary` **当文字色用了 117 处**（当背景只有 11 处），是宿主全站约定 |
| `.dsy-msg.warn` 的 `state-warn` 作文字 | 2.15:1 | 同上 |
| `.dsy-input` 默认边框 `border-l4` | 1.45:1 | 宿主 `Input.module.css` 的默认边框**就是** `border-l4`，完全一致 |
| 开关 OFF 态轨道对比低 | 1.45:1 | 宿主自己更差（`border-l3`，1.32:1）。插件用的 `l4` 反而比宿主更清楚 |

暗色主题下上述文字项全部通过（`label-tertiary` 8.54:1、`success` 8.00:1、`warn` 8.49:1）——
**本项目的对比度问题集中在亮色主题。**

`state-error`（`#ec1313`）亮色 4.50:1，实际是 4.49x，**恰好卡在 4.5 门槛下沿**；
宿主暗色换成 `#f25a5a`（5.55:1）就没问题。属边界情况，记录但不建议为此特判。
